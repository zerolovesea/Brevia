# Windows 后端实施记录

## M0：2026-10-18 目标机初测

设备为 Razer Book 13，i7-1165G7（4 核 / 8 线程）、约 16 GB 内存、Iris Xe，Windows 11 build 26300。
所有测试使用独立目录和只读模型，不修改已安装应用、会议或现有源码目录。Sherpa 固定为项目要求的 1.13.8，CPU 分析使用 4 线程。

已安装的旧 worker 收到 `--diarization` 后仍进入普通命令入口，返回 `Commands require id and type`，没有进入模型推理。此结果证明该包缺少当前显式分析入口，不能将旧包启动等待计作模型加载或推理耗时；新冻结包仍需单独构建验证。

此探针仅识别入口版本差异，不能单独证明旧实现的故障原因。后续通过旧包实际支持的 `meeting.refine` 复现并定位了继承管道阻塞，见文末。

0.5 秒采样可能错过短峰值。RSS 含共享页，不等于整机物理增量。最终采样三次均无受控分析进程残留。原始曲线、原生日志与 `report.json` 保存在目标机隔离目录的 `baseline-source-reaped`，不含会议数据。

Windows venv 的 `python.exe` 会派生真正执行推理的解释器；只终止启动器不足以确认资源回收。父端现在记录受控后代，并在关闭时等待整个子树退出，基线工具在关闭后追加采样。

将同一样例重复至 60 秒，三次冷启动收到结果分别为 18.750 / 18.375 / 18.937 秒；分割推理约 16 秒，模型准备至进入推理约 0.9 秒。树 Private Bytes 峰值约 946～947 MiB，RSS 约 592～593 MiB，三次退出采样均无受控分析进程。这是重复样例压力输入，不是 60 秒自然会议。上述源码初测使用隔离 Python 3.11.0；完整 worker 依照项目 CI 使用 Python 3.12，不能将初测解释为完整产品验收。

这些数据只验收短样本入口、基础资源采集与退出。尚未固定长会议、各语言 CER/WER、说话人标注、实时延迟和系统提交余量预算，不能据此默认启用复用、替换 ASR 引擎或宣称不存在泄露。后续实验必须保留按块隔离回退，并在同机完成质量、长会话与异常退出对照。

## M1：已实现的基础边界

分析模型和单块音频处理已从完整精修模块独立出来。入口仅导入音频、模型和必要配置；引擎只持有固定模型配置和模型对象，波形及当前块结果属于单次调用。当前生产路径仍按块退出，尚未接入多请求进程会话，不把可重复调用的 Python 对象等同于已启用进程复用。

管道限制响应行长度及消息队列容量；退出可以中断满队列读取和被大请求阻塞的写入线程。原生调用开始后使用单调墙钟计时，UI 暂停仅阻止下一块提交，不再暂停正在推理的调用预算。spawn 回收使用有上限的 terminate / kill 等待。

全局聚类固定人数时不计算两两距离；自动人数评分按约 8 MiB 行块计算，保留现有权重、候选筛选与决策方式。迁移对照的 60 组固定随机输入与原密集矩阵算法给出相同标签，回归测试覆盖固定人数跳过距离分配、3000 个声纹窗口的行块上限，以及模型重复调用后不保留单块波形。

仍需完成的 M1 内容包括带请求编号的 init / process_chunk / shutdown 会话、按目标机预算回收、整任务有限恢复及父端异常退出保护。预算和真实会议验收完成前不默认启用复用。

## 验证方式

Windows backend validation 工作流运行仓库检查、CPU 冻结构建、原生模型自检和冷入口基线，保存诊断与运行时构件，不发布应用。实机验收使用这些构件，避免以开发环境的成功替代安装包成功。

首轮 CI 的 CPU 依赖构建成功，但格式检查发现 Windows checkout 自动转换 CRLF，影响 178 个原本已通过格式检查的文件。工作流改为在 checkout 前保留仓库换行符，并将格式检查提前；不改写这批无关源码，也不关闭检查。

## 后续：有界会话与完整精修对照

上文 M1 基础记录对应 `1d0b40bc`。后续已加入任务内 `init / process_chunk / shutdown` 会话、请求序号、最多 10 个有语音块、软 / 硬内存阈值、系统可用内存保留量与有限恢复。启动、协议、低内存或清理失败不自动重试；同块最多额外一次、整任务最多两次异常恢复。Windows Job Object 在父进程异常退出时终止分析子树，Razer 已通过实际父端强退和正常退出用例。

复用默认关闭，仅设置 `BREVIA_ANALYSIS_BUDGET` 才启用。阈值覆盖当前 refinement worker 及后代的 Private Bytes 和整机可用物理内存；尚未覆盖兄弟 worker、系统提交上限及 GPU 共享内存，不能视为完整资源调度验收。

使用用户授权的一段 1129 秒单声道 16 kHz PCM16 录音，在独立数据目录按系统回放轨执行完整会议精修；不走可能跳过说话人分析的长文件导入路径。Windows 为 Qwen3-ASR 0.6B int8、自动语言、4 线程，包含 VAD、分析模型加载、说话人分析、ASR 加载、转写和持久化；不含文件复制、导入转换、双轨混音、Electron 启动与排队。

这是各路径各一次的探索测试，不能给出小幅性能差异的统计保证。macOS 使用 M4 Pro 及现有 MLX 路径，两端分块和 VAD 实现不同，不把跨设备差异归因于单一框架。Windows 两轮分别获得相同的 81 个原始分析片段和 74 条字幕；分析结果以及字幕的文字、时间戳、说话人和词级字段逐项一致，均无回退警告，退出后受控进程树为空。没有人工参考稿，不计算质量准确率。

初版复用比逐块隔离慢 6.6%，没有通过提速门槛，因此保持默认关闭。其采样 CPU 时间约 3406.5 core-s，逐块隔离约 3114.7 core-s（0.5 秒采样可能遗漏退出前的小段 CPU 时间）。分析阶段树 Private Bytes 峰值分别约 1255.1 / 1237.7 MiB，减少启动次数没有降低完整任务的内存峰值。

逐块隔离的 ASR 预热后 Private Bytes 基本稳定在 2789 MiB 左右，没有在本次约七分钟转写阶段内线性增长；单次长录音不能排除慢速泄露。整体峰值由 ASR 阶段主导，不能只凭分析模型复用解决。

随后将生产守护与完整诊断采样分开：生产阈值仅依赖 Private Bytes，不再重复执行昂贵的 USS 页面扫描；基准仍采集完整指标。该改动保留采样周期和同一内存预算，需要继续验证完整录音及重复任务，不因初版结果为负而放宽阈值。关闭 ORT 线程自旋的独立 60 秒公开样例实验反而更慢，未将此配置加入产品。

首轮统计脚本在精修完成后的结果整理阶段错误地从摘要读取 segments。原始计时和阶段日志保留；已从隔离数据库核对 refined 状态，生成单独的 validated-report，不重写原始记录。后续统计使用会议详情读取结果。

`3849f289` 对应的 Windows PR 构建通过完整检查、冻结、自检及三次会话结果哈希一致性检查，构件 ZIP SHA-256 为 `9647e4e88b0bcbb28d8abbff9c0498a2c330f1ce85877a3c1d0f1c65d39b50e9`。Razer 实机同样通过该冻结程序的三请求会话检查及退出验证。430 项后端用例与后续轻量守护版本另行验证；CI 跳过桌面 E2E，本机使用真实 Electron 验证。

## 已安装 1.4.2 的管道启动死锁

目标机仍为 10 月 17 日的 1.4.2。入口与精修源码归一化换行后与发布标签一致；真实日志在 10 月 18 日北京时间 10:49～11:11 反复记录启动阶段 120 / 240 秒超时，并递归缩块、降级，仍只处理到录音前 4 分钟。上文 808.39 秒是已包含启动修复的开发代码，不能作为已安装 1.4.2 的完整耗时。

使用隔离会议和 60 秒公开样例，通过旧冻结程序的正常 `meeting.refine` 协议对照：

| 条件                                  | 结果                                                   |
| ------------------------------------- | ------------------------------------------------------ |
| 旧包，命令 stdin 保持打开，无额外输入 | 两次均到 80 秒限时仍未启动分析；子进程 CPU 约 0.016 秒 |
| 同一旧包，第 10 秒开始向父端发送空行  | 子进程恢复启动，全流程 51.782 秒完成                   |
| 新冻结包，默认逐块隔离，无额外输入    | 41.031 秒完成，`refined`，退出无残留                   |

原生栈显示父端主线程停在 `worker.main → ReadFile`，分析线程等待结果管道；旧分析子进程停在 `Py_InitializeFromConfig → lseeki64 / fflush → SetFilePointerEx → NtQueryInformationFile`。输入唤醒对照证明继承的命令管道使子进程初始化被父端阻塞读取牵制，不能归因为 Sherpa 推理慢或内存不足。显式分析入口通过 `subprocess.PIPE` 创建独立 stdin，消除该依赖；启动错误直接结束任务，避免按音频故障多次等待。

冻结自检现在也让父端在仍打开的 stdin 上阻塞读取后再启动分析。测试控制器保持输入打开直至冻结程序退出，不能用 `communicate` 提前发送 EOF 绕过此条件；超时时回收受控子树。桌面验证 CI 额外构建完整安装包，并再次检查打包后使用的运行时。

随后使用同一已通过 CI 的冻结程序、默认逐块隔离和 4 线程，完整处理上述 1129 秒录音，含进程启动耗时 855.484 秒（14 分 15 秒），没有启动重试、降级或退出残留。81 个原始分析片段与 74 条字幕的文字、时间戳、说话人及词级字段与开发基线逐项相同。树 Private Bytes 峰值 2.724 GiB，ASR 连续运行约七分钟时基本稳定，接通电源且处于平衡电源模式。

这是单次冻结后端结果，不包含 Electron 完整应用验收，也不能证明不存在长期泄露。桌面应用的完整录音验收另行记录；未以缩小模型、降低质量参数或默认启用未通过门槛的复用来换取时间。
