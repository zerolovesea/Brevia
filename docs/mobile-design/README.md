# Brevia 手机端产品与界面设计

2026年10月8日 · iPhone 与 Android · 离线录音与连接设计

手机负责录音、可靠保存与展示；电脑负责语音识别、说话人处理、笔记生成和会议归档。首版仅连接同一局域网内的电脑，支持扫码或 PIN 配对。离开网络后，正在进行的会议继续在手机录音，恢复连接后补传。本文和设计图均为设计交付，尚未实现手机应用或通信服务。

界面采用**低密度、暖白与墨黑、以文字为中心**的方向。每屏一个主要任务，转写与笔记切换阅读，连接诊断收进二级页。后台录音的首要目标是保住音频；连接状态、转写进度和录音状态分别表达。

## 1 产品边界

### 首版包含

- 一部手机连接一台电脑，同一会议仅一个手机录音源。电脑可保存多个受信任设备，手机可保存多个电脑身份，但同一时刻只有一个活动连接。
- 局域网扫码、PIN 配对、受信任电脑自动重连；电脑通过以太网接路由器也可连接，只要与手机 IP 可达。电脑热点作为备选接入方式，需实机验证。
- 手机麦克风采集、本地持久保存、音频发送；电脑回传增量转写、已保存笔记与处理状态。
- 录音开始、暂停、继续、结束、重点标记；后台录音和中断恢复；会后列表、搜索、笔记、逐字稿、重点与音频回听。
- 已缓存内容离线阅读，待传录音保护，系统分享，设备信任与存储管理。

### 明确不包含

账号系统、多手机混音、手机 ASR/大模型、手机模型下载与 API Key 设置、手机系统音频采集、电脑与手机同时编辑同一富文本笔记。

“不负责计算”指不运行 AI 推理。采集、音频编码、加密、存储、渲染和播放是手机必要的基础能力。首版笔记只读回传；手机可以追加带时间戳的重点及短备注，不引入协同编辑引擎。

录音支持两种路径：连接电脑实时转写，或完全离线、仅保存在手机。离线录音不要求配对或电脑模型就绪；用户结束录音后，连接电脑并明确确认上传，才开始传输。手机仍不运行转写模型。

## 2 PC 视觉与能力依据

当前界面的视觉权威是 [frontend/tailwind.css](../../frontend/tailwind.css) 及 [现有会议截图](../assets/tour/zh/实时会议和翻译.png)：暖白底、炭黑主按钮、细分隔线、克制圆角和浮动录音条。源码中的字体为 Helvetica Neue / SF Pro Display / PingFang SC；控件圆角 8–10，面板 12，录音浮条 14。

[docs/design.md](../design.md) 中的紫色柔光方案与当前实现不同，手机设计不沿用其紫色渐变、大圆角卡片或环境动画。Impeccable 用于任务聚焦、渐进披露、低认知负担与无障碍检查，不替换现有品牌。

当前桌面流程由 [frontend/backend-client.js](../../frontend/backend-client.js)、[electron/main.js](../../electron/main.js) 与 [backend/worker.py](../../backend/worker.py) 串联，worker 使用本地标准输入输出协议。手机配对、局域网监听、鉴权、持久确认及结果订阅是新增能力，不能把本地 worker 直接暴露到网络。

现有 PC 允许用户配置云端文本 AI 服务。因此移动场景的准确隐私文案是：“音频仅在手机和已配对电脑之间传输；转写在电脑完成。若电脑启用了在线 AI，相关文字按电脑设置发送。”不能继续宣传“音频不离开手机”，也不能无条件称“全部内容不经云端”。

## 3 信息架构与低密度布局

一级导航仅三个入口：**会议、连接、设置**。会议内隐藏一级导航，返回列表不会结束录音；列表上方出现单行“录音中 · 返回会议”。同一时间只能有一场活动录音，点击新建时返回当前会议。

会议页分“转写／笔记”，回看页分“笔记／转写／重点”。设备状态摘要最多两行，点击进入连接详情；不常驻展示 IP、延迟、重试次数、电池和缓存容量。设置首页只有五行，复杂选项进入二级页。

| ---------- | -------------------------------------------------------------------------------- |
| 参考画布   | iPhone 390 × 844 pt，Android 412 × 915 dp；同时适配 360 宽小屏                   |

## 4 连接与权限

### 配对流程 A01 至 A04

1. PC“连接手机”显式开启配对窗口，展示设备名、二维码、6 位随机 PIN 和 2 分钟倒计时。关闭配对面板即关闭新配对入口，不影响已建立的受信任连接。
2. 手机选择扫码或输入 PIN。扫码时才申请相机权限；拒绝相机仍可用 PIN。首次访问局域网时解释用途并请求系统允许。
3. PIN 不是网络地址。先发现并选择电脑，再输入 PIN；发现失败可扫码获取地址，或在帮助页手动填电脑显示的局域网地址。手动地址仍须配对鉴权，不能直接信任。
4. 扫码内容带短时一次性凭据、协议版本、电脑标识和身份校验信息。两端显示相同验证词，PC 明确“允许连接／拒绝”。A04 中的等待授权是电脑允许连接，不是电脑替手机授予麦克风权限。
5. 允许后保存电脑身份与设备凭据；首次录音时再向手机系统申请麦克风权限。连接成功本身不会开启麦克风。

PIN 校验须防猜测：按设备与配对窗口限速，初始建议连续 5 次失败后冷却 30 秒；一次成功即失效。验证词来自受认证握手，不能仅由设备名生成。正式实现使用成熟的短码配对／PAKE 能力或等价的经过审查方案，禁止把 6 位 PIN 当长期密钥或自行设计加密协议。

### 连接界面

连接首页展示当前电脑名与“已连接／未连接”，主要操作为连接或返回会议。诊断页按顺序检查：局域网权限 → 地址可达 → 配对身份 → PC 服务 → 处理能力。失败分别显示“允许局域网访问”“检查是否处于同一网络”“在电脑允许连接”“请打开电脑版 Brevia”。

公共或访客 Wi-Fi 的客户端隔离、公司防火墙会导致同一 Wi-Fi 仍不可达。帮助页解释这一点，并提供使用可互通网络或电脑热点的办法，不建议关闭全部防火墙。断线原因不明时只说“暂时无法连接电脑”，不擅自断言电脑休眠。

## 5 会议中的交互

### 开始 B01

准备页仅保留标题输入、麦克风检测和一个就绪摘要。识别语言、工作区及处理方式进入“录音选项”二级表单，继承 PC 默认值。设备诊断、模型选择、算法参数不进入主页面。

点击“开始录音”时，先完成手机落盘能力与麦克风验证，再和 PC 建立会议身份。创建请求幂等；按钮显示“正在开始”，不能重复新建。只有本地首段音频写入成功后，才进入“正在录音”；超时显示可重试原因，不生成伪录音计时。

若 PC 未安装模型，准备页显示“电脑尚未准备好转写”。用户可回 PC 处理，或在明确说明后选择“先录音，稍后转写”；仍须完成配对与会议创建。

### 转写 B02

顶部依次为会议名、录音状态与累计录音时长、传到电脑的进度。正文以发言人和时间戳分段。未识别身份用“发言人 1”，不凭空生成姓名。草稿文字用正常可读的弱化色并标“识别中”，定稿在原位置替换，不能追加成重复段落。

默认跟随最新；用户向上阅读后停止自动滚动，出现“回到最新”。只在用户仍处于底部时跟随新段落。不逐字打字动画、不整页刷新、不朗读每一条流式更新。长按可复制或记重点；全部编辑校正在电脑端完成。

“已传到电脑 18:40”表示音频已被 PC 持久保存，不等于电脑已转写到 18:40。转写落后明显时显示“转写正在追赶”，而非网络断线。

### 笔记 B03

展示 PC 上已保存的笔记版本和更新时间，保留段落结构。AI 建议与已采纳笔记必须区分；未经确认的建议不冒充最终决定。电脑尚无笔记时显示“电脑生成或保存笔记后会显示在这里”，而不是永久加载。

笔记更新保留用户阅读位置；正在选择或复制文本时延迟视觉替换。手机首版只读，不显示可编辑光标或富文本工具栏。待办复选框是内容呈现，点击不修改状态；以后需要编辑时再引入明确的冲突规则。

### 重点与暂停 B04

点击“重点”立即按录音时间保存标记，轻提示“已记重点”，可打开抽屉添加最多 200 字备注。记重点不自动暂停；图中暂停背景仅是该示例所处状态。备注即使离线也可保存。键盘打开时底部操作保持可达，弹层支持关闭与返回。

暂停关闭采集并停止累计录音时长，已有音频可继续传输。继续需重新确认实际麦克风可用，不先亮起红点再等待采集成功。长时间后台暂停可能失去系统执行机会；首版提示“回到应用继续录音”，不播放静音音频维持进程。

结束弹出 G04。无论在线与否，先停止采集、关闭本地录音清单，再进入 D01。结束操作可重复重试但不可创建第二份会议。

## 6 录音与连接状态模型

用三个独立状态描述事实，界面取其组合，不使用一个“连接成功”掩盖其它问题。

| 维度 | 状态                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| 录音 | 未开始 → 正在开始 → 录音中 ↔ 用户暂停／系统中断 → 已结束；另有存储失败                   |
| 连接 | 未配对 → 配对中 → 已连接 → 重连中 → 离线；身份失效需重新配对                              |
| 内容 | 已在手机保存 → 待传／补传中 → 电脑已保存 → 转写追赶 → 笔记处理中 → 完成；各阶段可单独失败 |

| 组合                  | 用户看到什么                         | 系统行为                                           |
| --------------------- | ------------------------------------ | -------------------------------------------------- |
| 录音中，在线          | 录音中 18:42；已传到电脑 18:40       | 本地持续保存，发送音频，接收结果                   |
| 录音中，离线 C01      | 电脑已断开，录音仍在继续；02:14 待传 | 不停止采集、不丢弃缓存；冻结旧结果并标最后更新时间 |
| 录音中，恢复 C03      | 正在补传；转写正在追赶               | 去重补传，结果按原时间线合并                       |
| 连接正常，PC 推理失败 | 录音已保存；电脑转写暂不可用         | 继续可靠传音频，展示 PC 返回的错误与恢复入口       |
| 来电中断 C04          | 录音被通话中断；已保存至 18:42       | 停止虚假计时，记录缺口，回到前台恢复               |
| 存储不足 G03          | 录音已暂停；手机空间不足             | 保护已保存内容，停止新采集，提供清理与导出         |
| 已结束，未传完 D01    | 录音已结束；02:14 待补传             | 保留原电脑归属与任务，前台或系统允许时继续发送     |
| 手机进程退出 H02      | 发现未完成的录音                     | 恢复清单与缺口，用户决定继续或结束                 |

首次探测到连接短暂抖动时就更新“连接不稳定”，不要等待多个心跳超时才承认进度停滞。恢复成功只提示一次，不重复震动或弹 Toast。

## 7 可靠传输设计约束

以下为实现阶段应满足的协议语义，不是已经存在的接口。

### 本地音频优先

手机边采集边写入可独立恢复的短片段，建议约 1 秒一个逻辑分片；实际容器和落盘策略由录音原型验证。只有本地持久化完成才推进“手机已保存”游标。录音目录、片段清单和结束标记原子更新，崩溃最多影响当前尚未持久化的短片段，恢复页标明实测缺口。

容量可用 16 kHz、16 bit、单声道 PCM 粗估约 115.2 MB/小时；若实际使用 48 kHz 或压缩编码，按真实码率估算，不能沿用该数值。录音主流程不依赖网络发送队列腾空。不能因为缓存达到任意时长便默默删除最早片段。

存储低于安全余量时提前提示，可清理已确认同步的回看缓存；写入失败立即停止并保存已完成片段。未同步数据受保护，不参与自动清理。建议默认将已同步的手机原始录音保留 7 天；“已同步”需 PC 完整清单与校验确认，不能只看 socket 写入成功。

### 传输与恢复

- 会话以稳定 meeting ID 标识；每个分片包含 session／stream ID、递增序号、时间范围、校验值与格式信息。PC 对重复分片幂等，确认必须发生在持久写入后。
- 建议使用基于 TLS 的局域网连接承载控制与结果，音频发送采用有界队列和较小分片；补传流不能阻塞暂停、结束和心跳。实现可分控制与音频通道，选择以实测稳定性为准。
- PC 回报已持久化的连续游标及缺失范围；重连只补未确认数据，不能只从手机“已发送”位置续传。后台恢复和 PC 重启也遵守相同规则。
- 初始建议心跳约 5 秒、连续缺失约 15 秒进入离线；I/O 错误立即进入重连。前台重试间隔 1、2、4、8、15 秒并加入随机抖动，网络恢复事件触发立即尝试。后台定时并不保证精确，不把这些值写成用户 SLA。
- 首版补传按音频时间线顺序送入 ASR，新录音继续落盘并排队，明确展示“转写追赶”。这避免双路识别带来的重复文本与顺序混乱；恢复速度取决于网络和 PC 算力，不能保证几秒内追平。
- 转写与笔记事件带稳定段落 ID、修订号和事件游标。先补事件，再恢复订阅；事件保留期不足时取完整快照。草稿到定稿在同一段落更新，不能重复追加。
- 结束时发送最终音频清单；PC 仅在收齐并校验后标“音频完整”。录音结束、音频完整、转写完成、笔记完成是四个不同事实。

### 身份和归属

首次配对核验电脑身份，后续连接固定信任身份而不是固定 IP；IP 改变可重新发现，身份改变必须重新确认。凭据放入平台安全存储。电脑默认仅开放显式启用的局域网手机服务，所有请求都鉴权，不因同网段便信任。

手机只能读取 PC 为该设备授权的会议／工作区。默认同步手机创建的会议，开放其它历史会议须由 PC 用户选择。诊断日志不包含原始音频、转写正文、完整 PIN 或凭据。

活动录音中不切换电脑。取消信任前须结束录音；如仍有待传内容，明确告知其将保留在手机，重新信任原电脑后才能续传，并提供音频导出。不得将原电脑会议自动传给新配对电脑。

## 8 iOS 与 Android 后台行为

### iPhone

原生录音会话结合音频后台模式，是锁屏录音的基础；普通页面或 WebView 的存活不是录音保障。Apple 说明后台录音需要音频后台配置，且通话、闹钟等仍可能中断音频会话。[Apple 录音类别说明](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/record)

首次局域网授权必须在前台完成，并声明用途；Bonjour 发现需要相应服务声明。首次权限提示不能推迟到锁屏后再触发。[Apple 局域网隐私 TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)

F01 的 Live Activity 只呈现录音状态和返回入口，不负责录音或长连接保活。首版锁屏不显示转写正文、会议标题或停止按钮；即使用户关闭 Live Activity，也不应影响录音。系统 UI 样式由系统决定。[Apple ActivityKit](https://developer.apple.com/documentation/activitykit)

录音期间尽力发送，发送受限时优先落盘。录音结束或长暂停后不能假设应用永久在后台运行；未传完内容保持待传，下次前台或获得系统执行机会时继续。不要用“后台无限补传”文案。

### Android

用户在可见页面点击开始后，启动带 microphone 类型的前台服务，并满足录音和前台服务权限。Android 对后台创建此类服务有限制，因此首版不从开机、普通后台任务或电脑指令悄悄启动麦克风。[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)

F02 常驻通知显示状态、时长、暂停与返回会议。暂停后提供返回应用继续；停止录音仍进入应用确认。通知的实际可见性受系统版本、通知权限与厂商策略影响；权限被拒时给出解释和修复入口，不把通知未显示误判为麦克风未授权。

后台录音页提供电池策略诊断和“打开系统设置”，按厂商可用入口引导。不能用一个自制“后台录音开启”开关承诺绕过系统限制。用户强制停止、重启或系统终止后，应用不会承诺继续录音；重新进入时恢复已保存片段。

### 两端共同规则

来电或麦克风占用后，先保存断点并明确中断；返回应用后用户确认继续。耳机插拔和蓝牙路由变化不无声切换为错误音源：允许安全回退内置麦克风时提示，否则暂停。首版以内置麦克风为默认验证基线，蓝牙需独立覆盖路由测试。

PC 录音处理期间可请求防止自动休眠，但合盖、断电或系统策略仍可能断开。手机照常按离线流程处理，不宣称能唤醒电脑。

## 9 会后回看与分享

D01 的三个结果独立呈现：手机已保存、音频传输进度、电脑处理进度。返回列表或关闭页面不删除任务。PC 转写或 AI 笔记失败时，已保存的录音与已有逐字稿仍可访问。

D02 默认按会议开始时间排序。录音中、待补传、处理中、已同步、仅缓存用文字和小图标表达，不给每条会议加彩色卡片。搜索入口展开后可搜索已授权、已同步的本地文本；离线时明确范围为“本机已缓存会议”。

D03 点“来源 18:26”切到对应转写，若音频可用则定位播放。手机自行录制且仍保留的音频可本地播放；只有 PC 有音频的会议需在线流式读取或下载缓存。没有音频时显示 H03，不播放空进度条，不阻止文本阅读。

重点列表包含时间戳和备注；点重点进入原文。来自 AI 笔记的待办不自动等于用户标记的重点。全文搜索 D04 保持结果定位，播放只在用户点击后开始，不自动出声。

H04 选择笔记 PDF、转写 TXT 或重点 Markdown，再打开系统分享面板。手机可对缓存文本做普通格式导出，这不属于 AI 计算。首版仅导出已同步快照；内容不完整时标注“截至最后同步时间”。音频导出是独立操作，必须显式选择，不默认附带。

手机“移除回看缓存”只影响手机副本；首版不提供全局删除电脑会议，避免误删。清理前说明预计释放量，待传录音始终排除。电脑删除会议后，手机同步显示已删除并清理对应阅读缓存；尚未补传的手机原始音频保留，提供恢复为新归档或导出，不静默丢弃。

## 13 电脑端必要配套

P01 放在 PC 设置中的“手机连接”，显示手机连接服务开关、二维码、PIN、失效时间、局域网地址和已信任设备入口。配对服务默认关闭，由用户显式打开。画板侧栏仅示意本次配套入口，完整桌面导航沿用现有应用。新设备请求弹出 P02，显示设备名、平台、验证词与“允许连接／拒绝”，确认后记住身份。

PC 会议顶部标“输入：手机”，保留音频已收到位置与连接状态。手机作为本次会议唯一现场采集源；首版不同时混入电脑麦克风或系统音频，避免双重回声。电脑仍负责笔记编辑和推理处理。

手机断线时 PC 显示“手机暂时离线，等待补传”，不能擅自结束会议或把缺失音频补成静音后宣布完整。若 PC 用户手动结束，发送结束命令；手机离线时保留停止意图，重连后停止当前采集并将超出 PC 结束点的已录内容作为待确认续段保留，不能丢弃。首版推荐会议结束由手机主控，PC 远程结束必须确认并显示设备是否已收到。

## 2026-10-08 离线录音交互与实现

- 首次打开进入会议库，保留连接与设置导航；不把配对当作录音前置条件。
- 「新建录音」复用准备页。电脑不可达时进入「仅保存在手机」；电脑在线时可主动切换此模式。标题、会议语言、参会人数直接可见。人数留空表示自动识别，已知人数沿用 `num_speakers`，用于电脑端说话人区分，不承诺实时字幕立即区分全部参与者。
- 离线录音不创建桌面会话，不发送音频。暂停、重点、结束与意外退出恢复沿用现有本地分片及录音控制流程。录音页和系统通知显示「仅保存在手机」。
- 结束页明确「手机已保存／尚未上传」，主要后续操作为「上传到电脑」。配对本身不触发上传；有多场本地录音时逐场选择。
- 上传先连接原有设备页，再复用准备页确认目标电脑、语言、人数和桌面识别模型。能力检查失败不绑定会议、不删除文件；确认通过后持久化绑定，复用现有持久确认和断点续传。上传中断后只重试已经获得用户授权的会议。
- 本地会议可回听、导出 WAV，也可明确确认后删除。删除提示说明手机可能是唯一副本。上传成功不自动删除本机文件。
- 状态顺序：本地录音 → 仅保存在手机 → 用户确认上传 → 补传／电脑处理 → 已同步。配对、查看会议和恢复网络不会跳过用户确认。

现有九张设计参考图仍用于视觉语言；新增离线入口和准备页状态以当前 Flutter 实现为准，不把旧图中的「必须先配对」作为行为规范。

## WebRTC 跨网络连接

已接入可靠、有序的 WebRTC DataChannel，保留局域网 HTTPS、本地 PCM 录音与持久化确认机制。先在局域网建立设备信任，后续可在电脑配置自部署服务后跨网络连接；首次配对不开放公网入口。

电脑系统休眠时保留会议；手机显示加载条与“电脑已休眠或断开，等待开盖或恢复连接”，继续本地保存。电脑唤醒、网络切换或回到前台触发恢复连接，按电脑已确认的样本位置续传。

部署文件、加密边界、TURN 凭据刷新、平台后台限制与真机验收矩阵见 [手机跨网连接与恢复](../mobile-remote.md)。公网服务尚未部署，本机集成测试不能代替真实 NAT、锁屏和合盖测试。
