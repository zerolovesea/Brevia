# Brevia v1.2.0

## New

- Recognition now runs as **VAD segmentation → one high-accuracy decode**: a finished sentence appears right after each speech pause, instead of a half-line that keeps changing. Punctuation and casing come from the recognizer itself.
- Subtitles in meeting details can be **edited sentence by sentence and saved**; timestamps, speakers, and playback positioning stay intact.
- Pausing a recording is now shown clearly in the live header, the mini control, and the meeting library.
- The model library is trimmed to what the pipeline needs — sentence transcription, post-meeting refinement, voice detection, diarization, voiceprint embedding, AI notes, and caption translation — and is now generated entirely from `backend/models.json`, so every card shows the model's real name, its size, and its speed/accuracy rating (measured disk usage and memory floor where the manifest declares them).
- First-run setup lists the recognition models with a speed/accuracy scale and downloads only what you pick; the models that ship with the app (voice detection, diarization, voiceprint) are shown as already installed.
- Meeting setup gained a **recognition model** selector, and the live screen has the same selector, so the model can be switched mid-meeting.

## Improvements

- Live captions read like paragraphs instead of one sentence each: neighbouring sentences are coalesced up to roughly 110 Chinese characters (280 Latin) per caption, short sentences never stand alone, and the hard ceiling stays at 150 / 380. A VAD endpoint is deliberately **not** a paragraph boundary — in real meetings the silence after one has a median of 30–50 ms, so treating it as one produced 24-character fragments; a paragraph now breaks only on a genuine long pause (≥1.2 s), or after 8 seconds without new results.
- Transcription CPU time drops by roughly 74–82% and peak memory by 18–28% on the same sample audio.
- Recognition, translation, and AI notes all read the same confirmed captions, so text no longer duplicates or overwrites itself during a meeting.
- The default recognition model is chosen from the meeting language, and its mapping is declared once in `backend/models.json` (`default_for_languages` + `refined_priority`) and shared by the app and the worker. When the declared default is not installed, Brevia uses an installed model that supports that language instead of asking for another download.
- Advanced settings now label the post-meeting refinement and voice-detection options, including the per-language voice detection parameters and the live segment cap.
- Imported recordings skip speaker diarization automatically when the estimated preparation time exceeds the budget; the estimate scales with **physical** cores, so the decision is no longer twice as late on hyperthreaded machines.
- Error messages for a failed model download now distinguish disk space, integrity, and network failures instead of collapsing into one sentence.
- Refined subtitle timestamps — and the audio clips saved when you add a line to a voiceprint — now follow the recognizer's word timestamps instead of spreading each speech window evenly by character count, so a refined line starts and ends where it was actually spoken.
- Removed the streaming recognizer, punctuation models, the live noise-reduction stage, the efficiency-mode switch, and the second live refinement pass; they are no longer downloaded, loaded, or stored.

## Fixes

- Fixed characters lost where continuous speech was cut: the next decode now reaches 400 ms back before the cut, so a word split across the boundary is recognised again with full context (a sentence previously came out as "…放电现象则会，助手分析一番", silently missing "停止"). The repeated part is aligned away at the seam, preferring the newer decode when the two disagree.
- Fixed subtitles that ended in the middle of a sentence during continuous speech (podcasts, video audio, anyone who talks without pausing): the trailing sentence is now held and stitched onto the next segment with the right punctuation, instead of ending with a period the recognizer invented for the cut audio. The same pass removes words decoded twice at a hard cut.
- Fixed quiet speech that voice detection missed entirely — a line under background music, a phone voice, a soft-spoken participant. Audio between two detected speech regions is now transcribed instead of silently disappearing, in live captions and in post-meeting refinement alike.
- Fixed dropped words, duplicated seams, and misplaced sentence punctuation at hard cuts in continuous speech.
- Fixed speech padding being read as seconds, which re-decoded the entire audio history for every segment.
- Fixed long meetings stuttering during sentence-by-sentence translation, caused by rewriting the meeting record for every translated line.
- Fixed refined transcripts that could show a sentence twice after a manual correction followed by a re-refinement.
- Fixed refined transcripts from the current sentence-transcription models being shown as a plain "no timestamps" full-text view, which also hid the sentence-by-sentence editor.
- Fixed the download queue showing an internal model id (for example `qwen3.5-2b-q4km`) instead of the model name for built-in AI models.
- Fixed dark mode on the first-run model cards and the live model selector, where model names, taglines, and the speed/accuracy scale were unreadable.
- Fixed a restored recording reporting success even when recognition could not start; it now reports the failure so nothing is recorded without captions.
- Fixed refined transcripts joining two complete sentences into one when the first ended in a connective ("他是。我们是。" became "他是我们是。"): the offline pass no longer applies the live caption rule that stitches a dangling connective onto the next sentence.
- Fixed per-sentence subtitle edits being silently discarded for a meeting whose refinement model is no longer offered.
- Fixed the segment context menu (add to notes, add this audio to a voiceprint) not opening on refined subtitles.
- Fixed a character being dropped where two captions met when they happened to share a character but their audio did not overlap.
- Fixed advanced settings failing to save with "Invalid setting" whenever a whole-number default (for example the 22-second segment cap) was round-tripped through the interface.
- Fixed meetings started from a Japanese or Korean interface defaulting to "auto", whose default model does not cover those languages; the default meeting language now follows the interface language for Chinese, Japanese, and Korean.

## Notes

- Restoring an interrupted recording now repairs a meeting whose recognition model is no longer available before it starts, and reports an error instead of silently recording without captions.
- Upgrading removes the retired recognizer models from the local model directory and drops the unused `streaming_model_id` and `power_saving` columns from the database.
- Existing meetings that reference a recognition model that is no longer offered are switched to a model that is available for their language during the background maintenance run that follows launch.
- A model that is no longer offered cannot be downloaded again: the app would otherwise fetch several GB, only to delete it on the next launch.
