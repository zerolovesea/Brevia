# Brevia 桌面端设计与交互规范

本文供产品、设计与前端开发交接使用，以 `codex/ui-design` 分支 2026-11-06 的桌面实现为基线。后续改动涉及视觉或交互约定时，同步维护本文与对应源码。

## 1. 设计方向与决策原则

Brevia 是本地优先的会议记录工作台。界面围绕开始录音、边听边记、会后核对、带走结果四件事组织。视觉采用系统字体、黑白灰表面、紧凑控件、克制的边框与阴影。Orca 的桌面分区与控件比例、Codex 的可折叠会话导航是本次重构的参考，具体行为以 Brevia 已实现的会议流程为准。

产品与前端共同遵守以下原则。

- **把空间留给内容。** 笔记、字幕、纪要承担主要视觉重量；导航、配置和状态退到合适的层级。
- **用布局表达关系。** 通过对齐、间距、字重、容器和选中态区分分区。帮助文案只在用户需要作决定时出现。
- **操作靠近对象。** 工作区、会议与导出操作优先就近展开，关闭后能回到原对象继续工作。
- **编辑始终可控。** 保留草稿、明确保存状态，并发修改交给用户核对。异步结果始终对应发起操作时的会议与配置。
- **结论可以核对。** AI 结论保留原话来源、时间戳和依据状态。采纳或编辑后继续保留来源关系。
- **动效解释状态。** 页面切换、展开与处理进度提供反馈；可点击对象的位置和命中区域保持稳定。

新增入口前，先确定它属于会议导航、当前内容操作、全局设置还是后台状态，再放入对应区域。同一动作的不同入口共享业务处理与状态。

## 2. 页面骨架与信息层级

```text
主窗口
├─ 左侧会议导航，可收起
│  ├─ 品牌返回首页、新建、导入
│  ├─ 会议搜索
│  ├─ 工作区选择与管理
│  ├─ 工作区 → 会议树，独立滚动
│  └─ 最近删除
├─ 右侧工作区
│  ├─ 顶栏，侧栏切换、当前位置与全局操作
│  └─ 当前页面，按内容需要独立滚动
└─ 底部状态栏，设备、后台任务、使用统计与版本

设置模式
├─ 设置专用导航，搜索与分类
├─ 当前设置页面，居中的内容列
└─ 共用底部状态栏
```

### 当前布局基准

下表为 CSS 像素，适用于桌面窗口。具体组件的覆盖规则见第 8 节。

| 区域           | 当前基准                       | 使用约定                                   |
| -------------- | ------------------------------ | ------------------------------------------ |
| 会议侧栏       | 260px                          | 收起后释放整列，保留顶栏恢复入口           |
| 工作区标题行   | 最小 28px                      | 折叠工作区之间保持紧凑，会议数量不常驻显示 |
| 顶栏           | `--desktop-header: 40px`       | 保持轻量，给 macOS 窗口控制留出空间        |
| 底部状态栏     | 24px                           | 承载全局状态，引导页隐藏                   |
| 首页内容       | 最大 720px                     | 标题、操作、最近会议共用对齐轴             |
| 新建／导入内容 | 最大 740px                     | 表单按任务顺序纵向展开                     |
| 设置左导航     | 224px                          | 分类导航与右侧设置分别滚动                 |
| 设置内容       | 最大 760px                     | 表单标签与右侧控件列对齐                   |
| 会中双栏       | 笔记与字幕约 1.25∶1，间隔 10px | 笔记常驻，字幕可收起                       |

侧栏内只让会议树滚动，命令区和底部入口保持可达。滚动条采用细轨道、透明背景，侧栏悬停或键盘聚焦时显示滑块。使用 `min-width: 0`、`min-height: 0` 与稳定的滚动条占位，避免内容挤出布局或切换时横向跳动。

窄窗口按实际可用宽度降级。会中工作面使用容器查询，原因分支图在容器小于 550px 时纵向排列，准备页在 580px、420px 断点调整字段。新增页面复用邻近页面的断点策略，并检查长标题、多语言和缩放后的布局。

## 3. 视觉基础

### 颜色

使用语义变量。浅色与深色必须成对维护，状态含义还需通过文字、图标或形状表达。

| 角色／变量               | 浅色      | 深色      | 用途                 |
| ------------------------ | --------- | --------- | -------------------- |
| `--color-surface`        | `#ffffff` | `#0a0a0a` | 主工作面             |
| `--color-overlay`        | `#ffffff` | `#171717` | 菜单、popover 与浮层 |
| `--color-navigation`     | `#fafafa` | `#171717` | 导航与次级表面       |
| `--color-selected`       | `#eeeeee` | `#2a2a2a` | 选中、悬停与键盘定位 |
| `--color-line`           | `#e5e5e5` | `#2b2b2b` | 容器边界、必要分隔   |
| `--color-text`           | `#171717` | `#f0f0f0` | 主要文字、主按钮填充 |
| `--color-text-strong`    | `#0a0a0a` | `#fafafa` | 标题                 |
| `--color-text-body`      | `#333333` | `#d4d4d4` | 长文本               |
| `--color-text-muted`     | `#696969` | `#acacac` | 元信息与次级标签     |
| `--color-text-subtle`    | `#737373` | `#a3a3a3` | 占位、弱操作         |
| `--desktop-input-border` | `#d4d4d4` | `#404040` | 输入框与控件轮廓     |

成功、警示、危险与录音分别引用 `--color-success`、`--color-warning`、`--color-danger`、`--color-recording` 等角色。它们的主题定义位于 [tailwind.css](../frontend/tailwind.css)，桌面中性色覆盖位于 [desktop-shell.css](../frontend/desktop-shell.css)。深色中的 `--color-black` 已用于表达反相后的前景角色，新增组件优先采用含义明确的 `--color-text`。

原因分支图允许低饱和度色彩区分分支，当前色值为蓝灰 `#62828a`、棕 `#9c7753`、绿 `#67816b`、紫 `#87718d`。节点背景以分支色约 6% 与表面混合，悬停／展开约 12%。颜色表示分组，依据强弱由独立状态表达。

### 字体与阅读

- 使用系统无衬线字体。基础字体栈包含 `-apple-system`、`SF Pro Text`、`Helvetica Neue`、`PingFang SC`、`Microsoft YaHei`、Arial；部分控件直接使用 `system-ui`。
- 页面标题通常为 23–26px、600 字重。首页标题响应式为 26–38px；其较大的比例服务于开始操作。
- 设置分组标题 15px／600，设置项 14px／400。一般操作与表单 12–13px，时间与辅助元信息 11–12px。
- 会中笔记和字幕正文通常 15px、1.7 行高。长文本保留可选中、可复制能力。
- 时长、时间戳和统计值使用等宽数字排版 `font-variant-numeric: tabular-nums`，减少更新时抖动。
- 品牌字形使用现有 SVG 资源，静态源为 [brevia-logo.svg](../frontend/assets/brevia-logo.svg)。

### 间距、边界与圆角

以 4、8、12、16、24、32px 组织主要间距；已有控件内的 6、7、10px 等光学调整随组件复用。内容区用更大的间距表达分组，组内控件维持紧凑。

| 对象                 | 当前常用值                                        |
| -------------------- | ------------------------------------------------- |
| 普通按钮             | 高度至少 32px，圆角 6px，左右内边距 12px          |
| 首页开始操作         | 高度至少 42px，圆角 8px                           |
| 图标按钮             | 通常 30 × 30px；局部工具栏可采用现有紧凑变体      |
| 通用自定义选择器     | 高度 34px，圆角 6px                               |
| 准备页选择器／会议名 | 高度 38px／44px，圆角 8px／9px                    |
| 菜单                 | 圆角 8–9px，内边距 4–6px，选项约 30–32px 高       |
| 会中面板、设置分组   | 圆角通常 10–12px                                  |
| 标准桌面浮层阴影     | `--desktop-shadow`，浅色为 `0 8px 24px #00000012` |
| 控件菜单阴影         | `--ui-menu-shadow`，由桌面控件样式维护            |

同组设置项依靠行间距分离，边框用于组边界或必要标题分隔。高级设置与权限组共用柔和底色和对齐方式。主工作面保持平整，浮层通过边界和阴影表达层级。

## 4. 组件与交互约定

### 按钮、图标与输入

| 类型     | 表现与行为                                       | 当前入口                                |
| -------- | ------------------------------------------------ | --------------------------------------- |
| 主操作   | 前景色填充、反相文字，一个任务区突出当前推进动作 | `.ui-button-primary`、`.primary-action` |
| 次操作   | 表面色填充、细边框，视觉弱于主操作               | `.ui-button`、`.secondary`              |
| 危险操作 | 危险色文字或现有确认按钮样式，明确删除对象和后果 | `.ui-button-danger`、`.modal-danger`    |
| 图标操作 | 统一线框，提供可访问名称；简短补充优先 `title`   | `.icon-button`、`interfaceIcon()`       |
| 离散选项 | 展开菜单、当前值勾选，支持键盘导航               | `.ui-select`、`desktopSelect()`         |
| 布尔偏好 | 紧凑开关，展示真实保存值                         | 现有设置开关                            |
| 快捷键   | 点击后直接录制按键，支持取消、清除与恢复默认     | 通用设置的快捷键录制控件                |

图标通过 [ui-components.js](../frontend/ui-components.js) 的 `interfaceIcon()` 输出，24 × 24 viewBox、1.6px 线宽、圆端点，实际显示通常 14–18px。新增同义操作复用现有图标名称；标记重点使用书签，字幕使用字幕图标，AI 使用星形图标。

所有操作检查默认、悬停、键盘聚焦、按下、禁用、处理中、成功与失败状态。只呈现业务中实际存在的状态。处理中禁止重复提交，失败保留输入与重试方式。

### 浮层选型

| 场景                     | 承载方式             | 交互要求                                             |
| ------------------------ | -------------------- | ---------------------------------------------------- |
| 工作区选择、会议更多操作 | 锚定菜单             | 紧邻触发器，选中项清楚，长列表内部滚动               |
| 新建／编辑工作区         | 紧凑 popover         | 名称优先，描述按需展开，草稿在取消删除确认后仍可恢复 |
| 删除会议／工作区         | 锚定确认 popover     | 对象、后果、取消、确认形成清楚的阅读顺序             |
| 导出与分享               | 导出按钮旁 popover   | 内容选择、格式与推进动作集中，分享入口紧凑排列       |
| 查找与替换               | 当前工作面旁的侧面板 | 显示匹配、选择与替换范围，保留正文核对空间           |
| 手机配对、退出录音确认   | 原生 `dialog`        | 完整展示配对校验或退出后果，管理焦点与取消           |
| 后台任务、更新提示       | 状态面板／非阻断浮窗 | 可关闭、可返回处理，显示真实进度或错误               |

沿用已有 `positionFloating()` 等定位逻辑，依据触发器的实际位置计算，靠近边缘时翻转或限位。检查侧栏内、窗口底部、滚动后和缩放后的位置。

关闭浮层时恢复触发器或相应对象的焦点。菜单与 popover 支持 Esc、外部点击等既有关闭行为；原生对话框沿用其焦点管理。嵌套确认保留上层草稿。异步导出成功后，只关闭该次导出的浮层，提示使用提交时的会议名称。

### 状态与文案

- 状态贴近所属对象。保存状态属于编辑区，设备状态属于设备和底栏，任务进度属于任务面板。
- 成功通常使用小状态点或勾选加简短文字。权限、离线、已保留信任等状态保持相近的占位和字号。
- 同一区域的生成中提示保留一个主要表达位置，按钮与全局任务入口各承担操作和追踪职责。
- 标签直接表达对象与动作，例如“会议纪要”“逐字稿”“生成纪要”“连接新设备”。省去重复介绍当前页面的副标题。
- 删除到最近删除、永久删除、清空数据和覆盖编辑的后果必须可读。原话变化、依据缺失和同步冲突也需明确呈现。
- 在线 AI 的文字发送范围影响用户选择，需要在配置或确认环节说明。

## 5. 各页面的产品约定

### 首页与会议导航

首页上方按“标题 → 快速录音／新建会议／导入本地音频”组织，下方接最近会议。快速录音是主要动作，沿用最近成功录音的配置；新建会议进入准备页。最近会议使用平整列表，日期、名称、工作区与时长保持对齐，整行可进入。

首页保持静态工作面，当前已移除粒子波形动画。会议行悬停使用底色等反馈，保持命中区域、光标与位置稳定。刷新列表时保留用户正在悬停、编辑和浏览的上下文。

侧栏以工作区内的会议为主要导航，折叠与选择状态分别表达。工作区数量不常驻显示。批量选择进入紧凑工具条，退出后回到正常会议树。最近删除拥有自己的列表、恢复与清空语义。

### 新建会议与导入录音

两种流程共用准备页的排版与表单组件。新建流程依次呈现会议信息、来源、可展开的处理配置和开始动作；导入流程先选择或拖入文件，再完善信息与处理选项。选择来源时复用现有单选卡和设备控件。

本次常用字段优先显示，高级选项按需展开。文件、设备、模型与权限错误靠近相关控件呈现。开始前显示实际可用状态。导入历史录音的相对日期只能基于用户确认的会议日期推算。

### 会议中

笔记编辑器常驻左侧，右侧提供实时转写，用户可以收起转写来扩大编辑空间。编辑工具栏保持单行、紧凑并持续可达。标题区集中显示会议名称、录音状态、计时与保存状态。

底部控制栏集中放置字幕、翻译、模型、暂停／继续、标记和结束会议。当前布局已移除音源名称与装饰性电平占位。音源选择和设备诊断归准备页或会议信息。

用户上翻字幕时停止自动跟随，提供回到最新内容的动作。AI 建议的采纳和忽略由用户决定，采纳后保留对应字幕来源。保存失败时保留恢复与重试入口。

### 会议回看与来源图

回看默认进入会议纪要，笔记、逐字稿与会议纪要分别提供清楚入口。纪要区域先显示原因分支图，再显示可继续阅读的纪要全文，全文默认展开。

原因图采用树状曲线分叉，主题与分支卡片之间保留阅读空间。连线置于独立图层，卡片、原话与操作保留原生 HTML 交互。分支点击展开依据，时间戳回听，逐字稿入口定位对应内容。

产品与数据处理需维持以下关系。

- 结论保留引用时间、原话及依据状态，区分依据不足、缺失与原文变化。
- 编辑过的结论可辨认，并保留生成时的结论或来源关系。
- 精修改变分段后重新核对引用，失效引用呈现待核对状态，回听定位受有效性约束。
- AI 建议被采纳后保留来源；历史会议与新生成结果共用核对逻辑。
- 导出笔记或纪要可携带原因图与原话依据。Markdown 同步更新维护的区块，并保护用户在目标文件补写的内容。

少量通用、周会、访谈和评审模板用于组织生成结果。模板选择放在合适的准备或生成入口；日常回看将空间优先留给结果。

### 设置

设置采用专用左导航与居中内容列。分类为应用设置、AI 功能、设备与数据。页面标题稳定，分组标题较强、选项标签较轻、控件列整齐。高级参数按功能收进可展开分组，组内以行间距建立秩序。

- **通用**承载语言、外观、窗口与后台、动态胶囊预览和直接录制的快捷键。
- **进阶设置**将权限状态与音频、识别、说话人分离等参数分组，权限状态和数值控件对齐。
- **模型库**按用途与安装状态组织模型，突出名称、体积、能力和下载／管理动作，详情渐进展开。
- **AI 功能**区分会中笔记和会后纪要，以循环演示解释结果与用途。复用已经保存的供应商配置。
- **关于与更新**集中展示版本、更新操作与日志；更新浮窗与设置页共享同一更新状态。
- **存储与隐私**展示磁盘、会议与模型用量，目录操作和危险清理动作各成一组。累计会议、时长、字数和版本由底栏承担相应概览。

### 设备连接与跨端协作

首次连接页以动态背景和手机应用演示介绍用途，主要动作直接开始配对。已有信任设备后进入管理页，电脑与手机图形内展示应用联动，设备列表提供连接、信任与管理状态。常用桌面窗口优先一屏容纳核心内容，设备较多或窗口较矮时允许内容滚动。

配对使用二维码／配对码，并由两端校验后确认。设备已信任、服务已开启、设备当前在线、允许访问电脑会议分别表达实际含义。电脑会议访问按设备授权，撤销后收回相应读取与处理能力。

笔记有跨端更新时先提示，用户可比较再接受同步。会后处理由手机主动发起、电脑执行，任务状态和失败原因回到手机。对离线、重连与尚未同步草稿保留明确路径。

### 悬浮胶囊与实时字幕

自动胶囊在活动录音且偏好开启时，随主窗口最小化／隐藏出现。它承载计时、暂停／继续、结束、字幕预览和笔记／AI 建议查看。设置中的动态预览帮助用户理解实际形态。

胶囊区分悬停预览与固定展开，离开后按状态收起，按 Esc 可退出展开；暂停时停止电平与识别动画。保存成功提供短暂确认，保存失败保留重试。独立实时字幕窗口提供置顶和字号调整，沿用桌面的中性色、紧凑操作与内容排版。完整行为见[桌面使用指南](desktop-experience.md)。

## 6. 动效规范

共用时序由 [motion.css](../frontend/motion.css) 与 [motion.js](../frontend/motion.js) 维护。

| 角色               | 时长       | 用途                             |
| ------------------ | ---------- | -------------------------------- |
| `press`            | 80ms       | 按下反馈                         |
| `feedback`         | 120ms      | 底色、边框与文字反馈             |
| `state`            | 180ms      | 选中状态、小范围内容变化         |
| `surface`          | 220ms      | 工作表面变化                     |
| `spatial`          | 280ms      | 有方向关系的前进／返回与引导步骤 |
| `menu`／`menuExit` | 160／100ms | 菜单进入与退出                   |
| `exit`             | 140ms      | 通用退出                         |

常用缓动为 `cubic-bezier(0.16, 1, 0.3, 1)`。设置内容切换可采用 8px 纵向位移与 180ms 进入。方向导航复用现有前进、返回动画；同级切换通过选中态维持连续阅读。

交互行与卡片维持稳定位置，按下反馈保持局部。演示动画用于连接、AI 功能、胶囊和引导等解释性场景。响应 `prefers-reduced-motion`；窗口隐藏或偏好变化时落到真实终态，业务完成与 DOM 清理独立于动画是否播放。

## 7. 键盘、可访问性与错误恢复

- Tab 可到达菜单触发器、编辑区、操作和关闭按钮。当前键盘聚焦以底色、下划线或输入边框变化表达，沿用 [motion.css](../frontend/motion.css) 的统一规则。
- 自定义选择器支持方向键、Home、End，移动焦点与确认写值分开。使用 `aria-expanded`、`aria-current`、`aria-pressed` 等表达对应状态。
- 图标按钮提供可访问名称，长标题可截断并通过 `title` 补全。危险后果保持常规可读文本。
- 设置保存、录音保存、处理任务分别展示真实结果。失败保留草稿与重试，取消恢复前一有效状态。
- 查看旧会议时，回放与正在进行的录音分开控制。更新安装前核对录音、草稿与任务状态，沿用现有保护逻辑。
- 自动检查更新约每 24 小时一次，失败按 1、2、4、最高 6 小时间隔重试。提示延迟、手动检查与安装状态共用控制器；自动检查失败由后台重试，手动检查失败提供反馈。

### 接续一个需求

1. 产品明确用户对象、入口、主要动作、完成结果，以及空内容／处理中／失败／取消／恢复路径。

5. 实现后按下一节检查，在影响设计约定时同步本文。大规模代码改动按 AGENTS.md 安排独立 review 并记录。

## 9. 交付检查

产品与设计核对以下问题。

- [ ] 当前任务的主要动作能一眼找到，设置与状态有各自归属。
- [ ] 选项和分区通过层级表达，说明只在帮助决策时出现。
- [ ] 会中笔记常驻；回看首先可读纪要，原因图与全文顺序正确。
- [ ] 每个可核对结论能展开原话，失效引用、用户编辑和同步冲突可辨认。
- [ ] 删除后果、导出范围与在线处理的数据范围清楚。

前端核对以下问题。

- [ ] 浅色、深色、长内容、空内容、多语言与缩放下仍可读。
- [ ] 侧栏折叠、长列表滚动和页面切换保留操作上下文。
- [ ] 鼠标悬停稳定，计时与后台刷新保持控件位置稳定。
- [ ] 浮层贴近触发器，窗口边缘限位，关闭恢复焦点，Tab 与 Esc 可用。
- [ ] 同一任务的状态一致，失败可恢复，异步结果对应提交时的对象。
- [ ] 减少动态效果和窗口隐藏时功能完整，演示与真实状态可区分。
- [ ] 桌面改动按贡献规范运行 `npm run build`、`npm test` 与格式检查，并在实际窗口检查涉及的页面。
