# 桌面工作台设计 · 2026-11-04

在 `codex/ui-design` 分支实施，以 `main` 的 `1924a203` 为基线。桌面采用单一可收起的会议侧栏和独立工作面的新结构；本文覆盖旧规范中的桌面布局、比例与组件参数。手机端和官网保持原设计。

## 设计依据

用户指定 [Orca](https://github.com/stablyai/orca) 的设计语言、比例、按钮与交互为参考。已检查其 [README 界面截图](https://github.com/stablyai/orca/blob/main/docs/assets/readme-hero.jpg) 并读取实际源码：

Brevia 将这一结构用于找会议、录音、阅读和编辑。尺寸按会议内容适配，保留现有系统字体栈和品牌图形；Orca 使用的 Geist 不作为新增依赖，不宣称逐像素复刻。

用户随后提供了 Codex 截图，明确要求侧边栏直接显示会议并可收起。因此最终的信息架构采用工作区文件夹与会议标题树，撤去独立工具轨道和第二层会议库。Orca 继续作为色彩、比例和控件语言的参考。

手机、设置和底部状态在本轮再次对照对应源码后重做，不用会议页的紧凑表格推测所有页面。Orca 的手机演示是动态手机框；Brevia 使用现有真实手机界面预览，安装地址、配对码、信任设备与连接状态仍来自 Brevia。Orca 的账户用量摘要适配为 Brevia 的设备与后台任务摘要，不复制其账户、Relay或远程主机能力。源码中提到的旧手机 HTML 设计稿在 `main` 不存在；宣传合成图不能作为配对页面实际截图。

## 单一侧栏与工作面

左侧只有一个260px的会议导航，不超过1050px的窗口使用240px。品牌、搜索、开始录音、导入和工作区会议树位于侧栏内，底部保留会议库、最近删除与设置入口。首页、准备、实时与详情使用同一主侧栏；设置用自己的目录替代会议导航，不保留独立工具轨道或第二层会议列表栏。

会议按工作区分组，每组用文件夹式标题、展开箭头和数量组织。组默认展开，组头 `aria-expanded` 与实际展开状态一致；点击组头切换展开状态。会议用32px高的标题行呈现，不显示旧版状态、元数据或文档图标列。当前会议保留选中与 `aria-current` 状态；重命名、多选、工作区归属、删除和恢复继续使用已有业务。

窗口页头的 `#library-toggle` 显式收起整个侧栏到0px，工作面获得完整宽度；再次点击恢复。侧栏不会随悬停自动扩张。`Cmd/Ctrl K` 展开侧栏并聚焦搜索，查找会议时保留当前文档或实时会议。切换会议前检查笔记和纪要的未保存编辑，阻止直接丢弃修改。

工作面随当前任务切换内容，各区独立滚动。进入设置时，会议主侧栏隐藏到0px，设置目录宽280px、窗口不超过1050px时220px；返回会议库恢复用户原来的侧栏显隐偏好，设置页内不使用会议栏开关。短窗口可纵向滚动到操作，避免通过整体缩放压缩正文。

设置目录的返回行与搜索固定在顶部，分组列表独立滚动。目录分为「应用设置」（通用、进阶设置、关于与更新）、「AI 功能」（模型库、AI 功能、声纹管理）和「设备与数据」（设备连接、存储与隐私）。搜索实时筛选当前语言的实际入口名称，隐藏没有匹配项的小节；空结果显示「未找到设置」，清空后恢复。搜索不冒充全局配置内容检索，不会改变当前设置页或保存状态。

全宽底部状态栏高24px，设备入口显示真实短状态，完整设备名称由悬浮说明和无障碍标签保留。任务摘要显示数量、录音时间或错误；点击在当前工作面上方展开任务层，再次点击收起，`aria-expanded` 同步。任务层默认收起，宽360px并受视口宽度约束，距离窗口底部36px，最大高度为420px，并为短窗口上下保留84px；不遮挡状态栏，卡片内部保留真实进度、暂停、重试、最小化和恢复动作。

### 手机连接工作面

介绍页以左侧操作、右侧实际手机界面形成两列，宽窗口使用56px页边距与列间距。主标题60px、行高1.08，说明18px、行高1.65；中文标题限制为6em宽，保持「手机与电脑」的语义断行。平台标签明确 iOS 与 Android，主入口150×40px且使用胶囊圆角，已安装用户可直接开始配对。右侧300px手机框展示 Brevia 真实截图；语言切换时使用中文或英文预览。

真实连接服务开关、状态、能力说明和反馈放在介绍两列下方的支持区，通过页面滚动可达。介绍画布使用6px网格的淡点阵，其他设置页面保持干净的中性底色。窗口不超过1050px时隐藏静态手机预览，操作面居中且最大560px，标题缩为48px；预览不是交互控件，隐藏不会移除安装或连接能力。

页面状态为 `intro`、`install`、`pair`、`paired`。安装保留两个平台的真实下载和二维码入口；配对通过已有原生弹窗完成，页面上的返回、下一步、完成和再次配对只改变相应流程。已信任但离线的设备仍归入 `paired`，不会因掉线退回介绍。连接成功和审批同意按真实设备状态转入已配对阶段，轮询与语言更新不会重启动画或配对。

配对弹窗宽640px并受视口约束，二维码容器224px包含20px白边；复制六位码、倒计时、过期刷新、取消与错误反馈沿用原功能。收到审批请求时显示设备名、校验词及拒绝/允许操作，隐藏已无用的二维码步骤，保留「电脑确认后才建立信任」说明。

## 视觉与控件

布局采用单一会议侧栏和工作面，正文保留清楚的阅读起点与留白。窗口页头40px；常规操作32px、图标按钮30px、一般输入36px；控件圆角6px、菜单8px。导航与操作文字13px，图标通常16px；转写、笔记和纪要正文保留阅读所需的字号与行距。

| 语义        | 浅色                  | 深色      |
| ----------- | --------------------- | --------- |
| 画布        | `#ffffff`             | `#0a0a0a` |
| 导航 / 弹层 | `#fafafa` / `#ffffff` | `#171717` |
| 主要文字    | `#171717`             | `#f0f0f0` |
| 次要文字    | `#696969`             | `#acacac` |
| 分隔线      | `#e5e5e5`             | `#2b2b2b` |

## 动效契约

动效只解释已发生的导航、步骤或任务状态变化，不等待动画完成才处理下一次操作。以下是当前代码中的时序，换步、取消、同态刷新和减少动态偏好均有回归覆盖。

| 场景               | Brevia 实现                                                             | 来源与适配边界                                                                                                                             |
| ------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 进入设置工作面     | 180ms、`ease-out`；透明度0→1，向下8px回到原位。                         | 对照 Orca `main.css` 的 `settings-shell-enter`。设置内同级导航不重复淡出整页。                                                             |
| 手机流程前进／返回 | 280ms、`cubic-bezier(.32,.72,.24,1)`；从右侧／左侧40px进入，透明度0→1。 | 对照 Orca 手机流程的±40px与280ms位移；Orca 的透明度单独为200ms，Brevia 使用一个280ms时间轴。没有引入 Orca 的测高辅助器或持续手机漂浮动画。 |
| 详情内容标签       | 180ms，向下6px回到原位，正文透明度保持1。                               | 保留阅读连续性的 Brevia 适配；三个原面板及编辑器节点持续存在。                                                                             |
| 任务层展开         | 160ms，透明度0→1、从下方6px进入。                                       | 状态栏摘要向上展开的 Brevia 适配，真实进度不受动画影响。                                                                                   |
| 任务卡出现／退出   | 160ms进入、120ms退出；最小化／恢复反馈180ms。                           | 现有真实任务状态驱动；不伪造进度或完成时间。                                                                                               |

手机步骤动效只在可见页面发生真实状态转换时触发；同态轮询、语言重绘和隐藏页面更新不播放。新操作可取消未结束的视觉过渡；减少动态效果偏好或窗口进入后台时直接呈现真实终态。菜单定位和纠错面板不得因过渡漂移，纠错面板底边锚定当前录音控制栏或播放器的真实上沿，以适配24px状态栏和窄窗口换行。

## 实施边界

- `frontend/index.html`、`frontend/app.js`：单侧栏与工作面结构、工作区会议树、搜索与显式开关、会议切换及未保存编辑保护。
- `frontend/desktop-shell.css`：仅桌面加载的主题、公共控件、主侧栏、会议树、状态栏与任务上浮层。
- `frontend/desktop-workspace.css`：准备、实时、详情、设置和引导的内容结构与响应布局。
- `frontend/mobile-connection.js`、`frontend/ui-components.js`：复用原手机 API 的阶段导航、真实设备状态、设置分组目录、实际入口搜索与返回入口。
- `frontend/motion.js`、`frontend/motion.css`：设置进入、步骤方向、标签、任务及减少动态效果处理；不更改业务状态的生效时机。
- 测试覆盖相应交互及渲染；生成的 `frontend/styles.css` 只通过构建更新。
- 不更改跨端协议、IPC名称、持久化字段、录音保存和模型服务。手机与官网仍使用原加载入口；桌面样式不应用到它们。
