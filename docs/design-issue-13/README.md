# 实时编辑与查找替换约定

对应 [Issue 13](https://github.com/zerolovesea/Brevia/issues/13)。桌面端支持在录音中或会后修改已确认字幕，预览并批量替换当前会议的文字。本文保留实现边界、交互约定与验收场景。

界面沿用黑白文档风格、紧凑页头与现有内容分区。示例词为「北威亚 → Brevia」，示例时间、姓名与匹配数量均为演示数据。

## 三个内容页的统一布局

- 第一行只保留三个内容标签与当前内容状态，使用相同的标签宽度、下划线和行高。
- 第二行为共用操作栏。左侧固定「查找与替换」「编辑」，右侧放当前内容的专属操作；笔记无专属操作，逐字稿保留版本、搜索、翻译、精修，纪要保留复制、生成或重新生成。
- 操作按钮统一为 32px 高、18px 图标、14px 文字。工具栏上下各留 8px，正文起始处统一留 16px；笔记与纪要的一级标题统一为 32px。
- 编辑时，左侧原位替换为带文字的「取消」「保存」，保存失败显示「重试」；状态仍在导航行。编辑和阅读共用相同的工具栏高度，底部播放器保持固定位置。
- 纪要正文不重复绘制「会议纪要」标题行或第二套按钮。已有章节排版、逐字稿的说话人与时间戳继续按内容类型呈现。
- 窄窗口优先保留公共操作位置，较长的专属操作自然换行；不缩小文字挤入一行。切换标签只更新页头，不重建草稿编辑器。
- 保留无自动聚焦、无聚焦外圈、原文查找高亮与独立替换/撤销。标签支持方向键和 Home/End，Tab 进入后续操作。

实际运行回归由 `electron/test-e2e.mjs` 对三个页面的公共按钮和正文边界做坐标比较，并覆盖窄窗口、八种语言、编辑切换、保存失败后的草稿与重试。设置 `BREVIA_CORRECTION_CAPTURE_DIR` 可保存 `unified-notes`、`unified-transcript`、`unified-summary` 等运行截图；使用隔离的示例会议，不改写用户数据。

## 编辑、预览与结果反馈

### 录音中修改一段

已确认段落悬停或获得键盘焦点时出现编辑按钮；点击进入原位输入框，保留时间戳。正在识别的临时字幕只读。底部录音控制始终可用，修改文字不暂停录音。

输入框下只放「替换相同词…」「取消」「保存本段」。保存成功才退出编辑态；失败保留草稿并允许重试。编辑期间停止自动滚动，新字幕继续追加，提供「回到最新」入口。

「替换相同词…」不根据整句修改猜测要替换哪个词：已有文字选区时预填查找词，否则打开空的查找字段。如果当前段落有未保存修改，先在原位选择保存后继续或放弃后继续；取消则回到草稿。批量替换不混入未提交的段落草稿。

### 全文替换预览

实时转写标题行增加「查找与替换」。点击后打开右侧面板，不遮住录音控制；关闭面板回到原来的阅读位置。宽窗口为面板留出空间，让原文和匹配高亮同时可见；窄窗口使用覆盖式面板及内部滚动。

逐字稿、笔记和会议纪要都提供相同的「查找与替换」入口，分别处理当前内容。面板包含查找词、替换词、匹配数量、上下文预览，以及逐处勾选；逐字稿沿用时间戳，笔记和纪要显示出现序号。输入查找词时，原文和预览同步高亮，清空或关闭面板即取消查找高亮。默认选中当前查到的全部匹配；用户可以排除误命中。「全选」只选中当前结果，不提交。

主按钮随选择数量显示「替换所选 N 处」。查找、替换文字或所选项变化时，先更新预览；只有点击主按钮才写入。保存成功后显示「已替换 N 处 · 撤销」。取消或关闭不修改文字。

### 会后替换完成

会后从「会议库 → 会议详情 → 逐字稿 → 查找与替换」进入同一面板。保存后返回逐字稿，在原位置显示修正结果和「已修改」，底部播放器继续保留。

译文与会议纪要如已存在，显示「尚未更新」及对应更新入口。逐字稿替换不自动改写笔记、译文或纪要；笔记和纪要各自的入口只修改对应内容，并提供独立撤销。不存在相关内容时，不显示这条提示。

## 操作顺序

1. **发现错词**：在已确认字幕中选中「北威亚」，通过文字操作菜单的「替换此词…」进入；也可以直接点标题行「查找与替换」输入。
2. **输入正确词**：查找「北威亚」，替换为「Brevia」。立即显示「匹配 3 处 · 涉及 3 段」及每处上下文。
3. **核对范围**：默认处理本场当前可编辑逐字稿，取消勾选不应修改的位置；点击时间戳定位原段落。实时录音中不提供未封口音频试听；会后沿用播放器定位。
4. **决定后续行为**：录音中可勾选「本场后续字幕也应用此规则」，默认关闭。会后不显示这个选项。
5. **提交**：点击「替换所选 3 处」，按钮进入「替换中…」并防止重复提交。批次中的文字修改一起成功或一起失败。
6. **确认结果**：成功后展示实际替换数量和撤销入口；失败保留输入与选择，原文不变，提供重试。新字幕正常接收。

## 匹配和范围

| 项目         | 本轮方案                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 匹配方式     | 精确的字面文本匹配，区分大小写；中文可匹配句内词语                     |
| “全文”的范围 | 当前会议的当前可编辑稿，不跨会议，不同时改写原始与精修两版             |
| 查找单位     | 每个段落内非重叠的文字出现位置；不跨段落拼接匹配                       |
| 预览单位     | 每处命中可独立选择；同一段命中两次，计为两处、一段                     |
| 修改对象     | 只改当前入口的正文；逐字稿的时间、说话人、音轨、录音和重点定位保持原值 |
| 原始版本     | 历史原始稿按现有只读语义处理，查看时提示切回当前稿后替换               |
| 不开放的范围 | 模糊匹配、同音词推断、正则表达式、跨会议替换及全局词库                 |

「类似地方」先解释为用户明确指定的同一段文字。读音相近、语义相近或不同错写形式，不自动纳入；用户可分别查找并替换，避免把正确的人名、术语一起改错。

查找词为空、替换词为空、两者相同或未选中任何匹配时，提交按钮禁用并在字段附近说明原因。单段保存继续遵守现有非空和长度限制；超限时指出具体段落，不截断文字。

## 本场后续字幕规则

勾选后，当前勾选项的替换与规则启用作为一次操作确认。只对本场之后新确认的字幕应用「北威亚 → Brevia」，不修改正在变化的临时字幕，不改变语音模型的识别能力。启用前已排除的旧匹配不补改。

启用后标题行显示「本场规则 1」，点击可查看原词、替换词并停用规则。停用只停止未来应用，已经保存的文字保持现状。规则与当前会议关联，恢复同一录制时应恢复；结束会议后停止自动应用，不影响其他会议。

同一查找词不允许同时存在两个不同替换目标；再次设置时明确显示原规则并确认更新。多个规则以新确认字幕的原文为基准，优先处理较长的非重叠匹配，每处最多替换一次；替换结果不再次进入规则，避免连锁和循环。

## 保存、撤销和精修保护

- **编辑草稿**：页面刷新、新字幕到达、面板开关不应吞掉输入或选区。离开有草稿的编辑状态时，使用保存、放弃、继续编辑的明确选择。
- **预览变化**：录音中新增命中先提示「新增 N 处，更新预览」，不悄悄加入本次选中范围。点击提交时锁定显示过的那批匹配；勾选后续规则时，其后新确认段落由规则处理。
- **冲突**：提交前检查所选段落是否仍与预览基准一致；已经被另一操作修改或重新分段时，整批停止，保留字段并提示更新预览，不静默覆盖。
- **失败**：磁盘、桥接或后台错误都留在原状态，显示「替换失败，修改仍保留」。没有收到成功结果时不能显示「已替换」。
- **撤销**：逐字稿、笔记、纪要分别保留最近一次批量替换的修改前后内容，提供持续可见的撤销入口，不依赖几秒后消失的提示。撤销也按批次核对并提交；相关段落又被修改时停止并说明冲突，不能覆盖后续人工修改。再次替换只覆盖对应范围的撤销备份；重新精修后，旧逐字稿批次不再提供撤销。
- **规则撤销**：若该批次同时启用了新规则，撤销时停用该规则，并包含它此后自动修改过且仍可安全还原的内容；发生任何冲突时不部分还原。界面显示实际可撤销数量。
- **会后精修**：现有精修会重新识别并可能改变分段。开始或重新精修前沿用已有的修改风险确认，明确说明人工改句可能不再出现在当前稿中；用户取消时保留当前稿。不得自动跨新旧段落猜测迁移人工改句，不新增候选稿切换系统。
- **规则重用**：会后保留本场规则供手动重新应用；用户确认精修后，仍先预览再替换，不承诺重新识别会自动保留所有人工纠错。
- **派生内容**：修改成功即标记相应译文与已有纪要待更新；是否重算由用户决定。复制、导出和后续 AI 生成使用已保存的当前稿，未提交草稿不进入导出。

批量撤销只承诺本次操作的备份，不把现有「原始」标签重新定义成不可变的识别历史，也不承诺从任意旧版本恢复。

## 状态反馈

| 状态           | 展示与操作                                         |
| -------------- | -------------------------------------------------- |
| 尚未输入       | 输入字段可用，提示「输入要查找的文字」，主按钮禁用 |
| 无匹配         | 「当前逐字稿中未找到相同文字」，保留字段供修改     |
| 有匹配但未选择 | 「已选择 0 处」，保留全选入口，主按钮禁用          |
| 正在提交       | 「替换中…」，锁定提交字段与重复提交，录音继续      |
| 已保存         | 「已替换 N 处 · 撤销」，正文呈现已保存结果         |
| 保存失败       | 原文未改，草稿与选择保留，提供重试                 |
| 内容已变化     | 「部分内容已变化，请更新预览」，不直接写入         |
| 临时字幕       | 「识别中」，不出现编辑或替换入口                   |

键盘支持 Tab 进入字段和动作、Cmd/Ctrl+Enter 保存本段、Esc 关闭未修改面板；存在草稿时先走保留选择。Cmd/Ctrl+Shift+H 在逐字稿、笔记和纪要正文中打开对应范围的替换面板；笔记编辑器原有 Cmd/Ctrl+F 保留。打开页面、面板及编辑框时不自动聚焦，不显示聚焦外圈；键盘导航仍用底色和下划线提示，用户输入后的焦点及选区在刷新时保留。匹配高亮同时配合文字、数量和勾选状态，读屏不因新字幕反复抢焦点。

## 实现边界

- `frontend/app-meeting-detail.js` 读取后端选定的当前稿；`frontend/app.js` 管理段落草稿、保存及重新精修前的风险确认。
- `frontend/transcript-corrections.js` 管理查找替换、预览、高亮、撤销与本场规则界面。
- `backend/worker_transcripts.py` 提供命令入口；`backend/store_transcripts.py` 与 `backend/store_corrections.py` 在事务中统一处理文本保存、冲突校验、撤销、后续规则及派生内容过期状态。
- `frontend/app.js` 的 `meeting.stopped` 处理在配置可用时自动生成纪要，并不自动发起整场精修；后续生成读取保存后的修正文稿，已有结果则显示待更新。

保留既有保存入口兼容性及协议字段命名。每批最多 500 段、合计 60000 字；超过时保留选择并提示缩小范围，不以后台分批破坏整批原子性。

手机端未开放编辑入口。完全离线录音没有可编辑的实时逐字稿；手机麦克风模式与电脑共享转写结果，不在手机另存一套修正文案。

## 评审和验收场景

1. 录音不停：修改旧的已确认段落时，新字幕继续到达，焦点、选区和草稿保持稳定。
2. 同段多次：一段出现两次查找词，只选一次时，另一处保持不变，数量按出现位置计算。
3. 预览后新增字幕：原批次不自行扩大，未来规则根据用户选择生效。
4. 保存中失败：没有半批成功，草稿保留；重试不会重复替换或重复启用规则。
5. 替换后继续修改：撤销遇到新修改会停止并说明，不丢失新内容；规则产生的后续修正也计入撤销检查。
6. 重新精修：出现人工修改风险确认，取消后当前稿不变；确认后可重新预览并应用本场规则。会议结束时的纪要生成读取已保存的修正文稿。
7. 译文与纪要已存在：逐字稿替换只标记待更新，手写笔记不变；笔记与纪要可从各自入口独立替换和撤销，Markdown 格式保留，旧快照不能覆盖后续修改。
8. 长会议、深色和小窗口：结果列表独立滚动、命中可定位、控制条始终可操作；不靠缩小字体适配。
